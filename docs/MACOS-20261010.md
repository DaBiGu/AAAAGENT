# Mac 0.3.0-dev.1 同步与验证范围

[安装与配置](SETUP.md) · [平台差异](PLATFORMS.md) · [第三方声明](../THIRD_PARTY_NOTICES.md)

本开发候选把 Mac 公共源码同步到 2026-10-10 交接基线，采用根目录 `code/desktop-pet/`、`code/workbench/` 和独立 `t3-source/`。产品基线与 Windows 同期，平台宿主和运行文件分别构建。本文区分包内历史 Mac 证据与本轮在 Windows 主机上的共享代码检查；不是 Mac 稳定版或全部验收通过声明。

## 功能和平台边界

同步范围包括陪伴与严格记忆、上下文预算、管理网页、微信、项目记忆及 T3 / Codex / DSH 连接。Mac 保留 Swift / AppKit / WebKit 宿主与 Darwin 运行锁，不能改用 Windows Electron、Node 二进制或 Windows 引擎清单。

固定工具链为 Codex **0.160.0**、DeepSeek Harness **0.2.0-rc.2**、Node **24.13.1**、pnpm **11.10.0**。T3 上游固定为 `c13f7d93fff0f578886985a3f673b4b21b7f6ac8`；本目录是包含 AAAAGENT 补丁和界面覆盖层的源码快照。引擎目标为 `darwin-arm64`；Intel Mac 未完成本轮固定运行包验收。

Mac 此次不加入 Windows 的本地 ASR、TTS 或 Ollama / Qwen 前台对话扩展。云端对话、语音、感知、准入与严格记忆各自沿用配置，不能称为全离线。既有唤醒词检测是单独能力，资源与实体效果仍需另验收，权重不随源码分发。

视频桌宠来源为 PC2005-cloud 的 [dsh-pet](https://github.com/PC2005-cloud/dsh-pet)，代码 MIT；动画、提示词及源视频适用上游非商业条款。T3 来源为 [T3 Code](https://github.com/pingdotgg/t3code)。原始媒体、购买的 Live2D、Cubism vendor、模型权重、账号、密钥与私人运行记录均排除；公开构建不得把缺资源占位报告为角色加载成功。

## 本次公开配置修复

私下交接源码中的配置、账本和业务数据分别使用内部评测目录与 `data/desktop-pet/`，与已有公共首次配置工具的 `.local/` 约定不同。直接覆盖会造成设置页、启动器和管理页读取不同位置。

公开版已将首次设置、配置校验、启动器、后端管理、音色 / 微信 / 项目数据、工作台 profile、日常打开与重启入口统一为：

- `.local/model-evaluation/trial/user-trial/`：配置、激活和管理会话。
- `.local/model-evaluation/`：共用账本、运行锁与本地运行记录。
- `.local/data/`：陪伴、项目、微信、音色和工作台私人状态。

原有配置摘要、准确运行指纹、外部凭据权限、当前会话身份和原生 SID 校验保持有效。不会自动迁移旧私有交接数据、采纳未登记账号或回退全局执行器。历史评测脚本与旧证据路径不因这项修复统一改写。

网页首配和配置文件入口共用运行文件登记逻辑，包含已安装的管理网页、工作台桥接、项目引擎 profile / 清单与内嵌 `/native/` 网页。项目引擎存在时，准备配置前还会验证该 profile 和完整运行包；缺项、符号链接或变化的已登记文件不会绕过启动校验。安装顺序与打包命令见 [Mac 固定引擎说明](../code/workbench/integration/engine-pins/README.md)。

视频角色的首配、后台目录与管理预览可在没有 Live2D / Cubism 的安装中使用；媒体缺失、路径越界或冲突别名仍被拒绝。目录允许同一视频在多个分组使用不同显示名称。同时安装 Live2D 时保留其目录和准确模型身份，视频渲染器复用已有语义预设，未放宽 Cubism 身份校验。

保留公共 `configure-local`、`doctor`、发布 / 首配测试及原生构建入口。共享 `build` 编译 TS 与微信 JavaScript / WASM；`build:macos` 另包含桌面网页、Darwin 唤醒依赖与 Swift 原生构建。Mac 专属步骤不会在 Windows 上假装成功。

## 包内历史 Mac 证据

10/10 交接清单记载：10/9 在 Mac 上，Codex 与 DSH 各完成两轮实际工程任务，生成并运行 Python 依赖调度程序，输出 JSON / 文本 / Mermaid / SVG，随后在原会话读取结果并写入后续文件。记录的生成程序测试为 Codex 8 项、DSH 26 项。

这些是交接包声明的历史结果，本轮没有重新调用实际执行器或复测 Mac UI。它们也不等于桌宠全部回归、Swift 构建、完整原生 App 双向同步或设备验收。交接清单仍列出复杂页面 Mermaid 显示为代码块、DSH 本地图片预览曾显示不可用等显示问题；不能以文件生成成功替代页面效果验收。

## 本轮共享代码检查

本轮整理环境为 Windows，复用同版本依赖只用于 TypeScript / JavaScript 检查，不把 Windows 原生模块当成 Mac 运行包。

- `npm run build` 完成共享 TS 与微信 JavaScript / WASM 构建。
- T3 服务端打包及普通 Web 编译完成；依赖复用仅服务于编译检查，输出不是已验证的 Darwin 原生运行包。
- 桌面网页与管理预览构建完成；桌面相关受控测试 8 项通过，2 项 Mac 专属检查跳过。Swift 宿主没有在 Windows 上编译。
- Mac 运行包整理的合成文件测试 5 项通过，并确认 Windows 主机拒绝打包 Mac 运行时；这不是实际 Mac 打包验收。
- 新增公共路径与运行登记测试 5 项通过：首次设置、启动器和业务数据库指向同一 `.local/` 布局；旧内部位置、越界运行文件和仓库内凭据仍被拒绝；合成的管理页、引擎和内嵌网页被登记，缺项、已变更文件及链接目录被拒绝。测试没有执行合成引擎文件。
- 视频目录与管理资源测试 5 项通过：无 SDK 的视频目录和固定路由、缺失媒体拒绝、路径 / 冲突别名拒绝、上游式合法显示别名及双模式 Live2D 身份保留。另使用交接包的真实目录元数据和临时单字节占位文件核对格式：165 条分组记录合并为 162 个资源条目，生成 18 项语义预设及预览路由。此检查未读取或解码真实媒体，完整目录也未加入公开仓库。
- 三份过期供应商测试 fixture 已按现有契约修订，相关 49 项受控测试通过；没有为通过测试降低生产校验。
- 首次设置集成测试的当前路径预期已同步。该组涉及 POSIX 文件权限和符号链接，本轮不以 Windows 主机结果声称 Mac 首配端到端通过。

修订后全量共享测试 **637 项中 613 项通过、24 项失败**：23 项为 Windows SQLite 清理占用，1 项依赖 POSIX 权限。发布测试组 **142 项中 90 项通过、52 项失败**：50 项涉及私人通道文件的 POSIX 归属校验，1 项 SQLite 清理占用，1 项权限模式差异。保留这些 Windows 主机限制，不把失败改成跳过或降低生产权限检查，也不声称 Mac 真机全量已通过。

共享代码检查不会启动真实模型、下载权重、登录账号或调用云端生成服务。Swift / AppKit / WebKit、Mac 麦克风与摄像头权限、物理扬声器、微信投递、唤醒准确率、长时运行及本轮 Mac 原生会话互通仍需在目标机器验证。

## 需要保留的已知风险

Windows 同基线的一次完整后端试验存在前台准入 `none`、云端严格记忆 `forget` 分歧，并触发 `source_expansion_contains_future_message`。该问题涉及共享记忆逻辑，本次未放宽保护，也没有在 Mac 实测复现或宣称修复。原始严格响应仅保留摘要哈希，合成计划复现不是原始响应回放，详见 [Windows 本地 LLM 已知问题](../windows/docs/LOCAL-LLM.md#完整后端与已知问题)。

Windows 的三 ASR / 三 TTS、4B 延迟与失败、9B 取消试验均不计入 Mac 推理证据。Mac 没有本地模型结果；源码构建和受控测试也不能推导真实模型质量、账号权限、音色效果或设备兼容性。
